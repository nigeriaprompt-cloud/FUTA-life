# FUTA World — building interiors

Tap a building on the map → **Enter** → `interior.html` opens the inside of that building, with furniture to use and NPCs by the Nigeria clock.

## How it fits together
| Piece | File | Job |
|---|---|---|
| Map hook | `public/world/game/interiors/hook.js` (loaded at the end of `world/index.html`) | `FUTA_INTERIOR.enter(building)` → navigates to `/world/interior.html?id=…&n=…&ty=…&r=…`. The map's `entryOf` now gives **every** building (lod < 3) an `interior` entry unless it is a compound (forecourt first). |
| Page | `public/world/interior.html` | Loads the scripts, reads the URL, starts the engine. |
| Engine | `game/interiors/engine.js` | Walking player, tap-to-use furniture, NPC schedules, HUD, ATM, live room, leave. |
| Salon screen | `game/interiors/salon.js` | Hair/beard picker for `get_hair` (see Hooks below). |
| Templates | `game/interiors/tpl_*.js` + `templates.js` | One template per kind of building; `classify(building)` picks it (name rules, then `type`). |
| Furniture / activities | `furniture.js`, `acts.js`, `interior/activities.json` | What each object is and what it lets you do (effects + which venues allow it). |
| Server | `supabase/03_activities.sql` (generated by `tools/build-options.py`) | `do_activity`, `enter_building`, `leave_building`, `get_stats`, ATM RPCs (banks only). |

## Rules (enforced by tests)
* ATM only in banks (client furniture rule **and** server `require_venue('bank')`).
* Security NPC with `hours:'always'` in every bank, library, lecture theatre, auditorium, computer lab, lab, faculty, admin office and primary school.
* Every building gets an interior and NPCs.

## URL parameters of `interior.html`
`id` building id · `n` name · `ty` type · `r` return url · `tpl` force a template id · `hour` Nigeria hour (preview) · `d` day 0-6 (preview; weekdays matter for `work`/`class` NPCs) · `fast=1` short activity timers · `peers=1` fake other players (demo) · `hud=0`.

## Game data: demo vs real
`FUTA_CONFIG.demo === true` (default in `onboarding/config.js`): stats, wallet and cooldowns live in `localStorage` (`futa.demo.play`) with the same rules as the server. `demo:false`: the engine calls Supabase RPCs through `FutaApi.rpc` and joins the live room `int_<buildingId>_1`.

## Hooks other code can provide
* The **wardrobe** (activity `wardrobe`) opens the phone's **Clothes app** right inside the room: `FutaPhone.show(true); FutaPhone.open('clothes', {hideOnClose:true})`. Back (or the home bar) closes the app, puts the phone away and returns to the room; it never changes the player's remembered phone open/closed choice. Opened from the phone's own home screen, Back goes to the phone home screen as usual. An unsaved outfit asks for a second Back press.
* The **salon / barber** (activity `get_hair`, on the salon chair and wash basin) opens `interiors/salon.js` (`FutaSalon.open`): live 3D preview, hair **style** (filtered by gender: each style in `avatar-options.json` has `for: 'm' | 'f' | 'u'`), hair **colour**, **shuffle strands**, and **beard** for men. Only `look.hair` / `look.beard` change. **Pay & save** first calls the server activity `get_hair` (takes the ₦ price from the pocket, +mood, 120 s cooldown), then `save_avatar`. If payment fails (no money, cooldown) nothing is saved. After saving the player model and the phone's user are refreshed (so the Clothes app starts from the new hair) and other players are told (real mode).
* Both need a signed-in character; otherwise they say so. Fallback if `FutaPhone` / `FutaSalon` are missing: `window.FUTA_OPEN_CREATOR(returnUrl)` or `signup.html?stay&edit=look&r=<this page>`.

## Adding things
* New furniture: `furniture.js` (`FutaFurn.def`) → list its activities in `acts.js` `propActs`.
* New activity: `interior/activities.json` → `python3 tools/build-options.py` → re-run `supabase/03_activities.sql`.
* New building type: `tpl_*.js` `FutaTemplates.def(id, spec)` + a rule in `templates.js` `BY_NAME` / `BY_TYPE`.

## Salon money + look sync (2026-10-17)
* **Hair costs money only in a salon.** Sign-up (`onboarding/`) stays free. After sign-up the creator's Hair tab is locked (`lockHair`) and the server refuses hair/beard changes in `save_avatar` (`hair_requires_salon`).
* The salon calls the RPC `save_hair` (`supabase/09_salon.sql`): charge + save in ONE transaction, so nobody pays without getting the haircut and a failed save never takes money. In demo mode `api.saveHair` (engine.js) runs the same checks locally.
* **Everyone sees the new look.** After any save (salon, wardrobe/Clothes app) the engine swaps the player's own model and calls `live.setLook(hash)`. `live/live.js` now drops the cached profile of a player whose presence hash changed and re-fetches it, so `live/remotes.js` rebuilds that avatar (before this fix other players kept the old look until they reloaded). Test: `node tools/test/live.test.js` ("look change reaches other players").
